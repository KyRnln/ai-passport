# Assets

This directory stores reusable fonts, images, music, and sound effects, organized by asset type.

Keep each asset in the matching subdirectory and document its destination, naming, integration method, and source/license. Do not mix binary assets with Markdown documentation.

## Fonts

Store reusable font files and generated font sources in `fonts/`.

| File | Type | Use and source |
| --- | --- | --- |
| `fonts/fusion-pixel-12px-monospaced-zh_hans.ttf` | TTF, TrueType outlines, 12 px grid | Source font for the current UI: Fusion Pixel Font 12 px Monospaced, Simplified Chinese variant (`Fusion Pixel 12px Mono zh-Hans`, 2026.10.16, by TakWolf). Its `name` table (ID 13) declares the **SIL Open Font License 1.1**, which allows commercial use, embedding and redistribution as long as the copyright notice and licence text are kept; the release also ships the OFL texts of the patch glyph sets it fuses (Ark Pixel, Cubic 11, Galmuri). Not committed here; download the 12 px monospaced TTF zip from <https://github.com/TakWolf/fusion-pixel-font/releases>. |
| [`fonts/app_font_24.c`](fonts/app_font_24.c) | LVGL 9 font, 4 bpp with only full-on/full-off pixels, 24 px | All main text: titles, metric values, settings rows, top bar and provisioning body. 24 px is exactly 2x the design grid below. |
| [`fonts/app_font_12.c`](fonts/app_font_12.c) | LVGL 9 font, 4 bpp with only full-on/full-off pixels, 12 px | Hints, notes and message text, at the font's design grid size. |
| [`fonts/proggy_16.c`](fonts/proggy_16.c), [`fonts/proggy_32.c`](fonts/proggy_32.c) | LVGL 9 fonts, 1 bpp, 16/32 px | Older ASCII-only pixel fonts, retained as reference assets and no longer compiled into the application. |
| [`fonts/ProggyCleanSZ-1.ttf`](fonts/ProggyCleanSZ-1.ttf) | TTF, TrueType outlines | Source of the retained reference fonts: ProggyClean by Tristan Grimmer (2004), a free pixel font whose license permits redistribution. Not shipped to the device directly. |

These two generated files replaced an earlier subset that was rasterized from a commercial
Hanyi face held under a personal non-commercial licence, and then a GNU Unifont subset
whose 16 px grid could not go smaller while staying pixel-exact. The Hanyi-derived files
shipped glyph data the licence did not permit this repository to redistribute; they were
removed, and the Unifont subset was replaced for the smaller grid. Both remain in earlier
commits of the repository history.

The current fonts are generated by this repository's own converter (`fontTools` plus a
built-in scanline rasterizer), because `lv_font_conv` needs Node, which is not
available in this environment. Run from the repository root:

```bash
python tools/gen_cjk_font.py --font <path>/fusion-pixel-12px-monospaced-zh_hans.ttf \
  --size 24 --name app_font_24 --output assets/fonts/app_font_24.c --snap
python tools/gen_cjk_font.py --font <path>/fusion-pixel-12px-monospaced-zh_hans.ttf \
  --size 12 --name app_font_12 --output assets/fonts/app_font_12.c --snap
```

The design grid matters more than the number in the file name: this font has
`upem = 1200` and places one design pixel every 100 units, so its em grid is **12 px**
and every outline coordinate is a multiple of 100. Generate at multiples of 12 px — the UI
uses 24 px for main text and 12 px for hints — otherwise one design pixel maps onto a
fractional screen pixel and the glyph edges anti-alias into gray. `--snap` pixel mode
additionally thresholds coverage to fully-on/full-off and rounds each advance to a whole
pixel, so glyphs land exactly on the panel grid and text is pixel-exact. Line height and
baseline are taken from the subset's real ink bounds (plus a 2 px leading) instead of the
font's own line metrics: the ink spans 18 px above and 4 px below the baseline at 24 px
(9 px and 2 px at 12 px), giving `line_height` 24/13 and `base_line` 4/2. Because the
half-width Latin glyphs are 16 px tall against the 18 px CJK ascent at 24 px, Latin-only
labels such as the metric names and values sit 2 px lower than CJK text on the same
baseline; `main/pc_ui.c` places those labels so their ink is centred in the space they
occupy. Both sizes together cost about 82 KB of Flash (65 KB + 16 KB of glyph bitmaps) and
are registered in `main/CMakeLists.txt`.

The character inventory is derived from the string literals of `main/*.c` (comments are
ignored), so regenerating after any text change fails loudly instead of shipping a
missing glyph; the monospaced release omits some complex glyphs the proportional release
covers, so a future missing-glyph error means switching to
`fusion-pixel-12px-proportional-zh_hans.ttf`. `--print-inventory` lists the covered
characters and `--dump-codepoint` prints one glyph's bitmap for review without a device.

- Use descriptive names that include the family, weight, size, and format when relevant.
- Document the source, license, character range, conversion command, and expected destination.
- Check Flash and internal-RAM impact before adding a font; the ESP32-C3 has no PSRAM.
- Do not commit fonts whose license does not permit redistribution.

## Images

Store reusable source images and generated display assets in `images/`.

| File | Dimensions and format | Use and source |
| --- | --- | --- |
| [`images/home.jpg`](images/home.jpg) | 3840 × 2160, JPEG | Product hero image embedded in both project README files to foreground AI Passport and its open, maker-oriented identity. |
| [`images/readme-hardware-specs.png`](images/readme-hardware-specs.png) | 2172 × 724, PNG RGBA | Optional technical infographic retained as a reference asset; it is no longer used as the homepage hero. Generated for this repository with the built-in image generation tool on 2026-09-17; the six labels and values were checked against the documented hardware contract. |
| [`images/logo-wordmark.png`](images/logo-wordmark.png) | 1648 × 336, PNG RGBA | Transparent black wordmark extracted from the repository's original `images/logo.png`; embedded in both project README files for light backgrounds. |
| [`images/logo-wordmark-dark.png`](images/logo-wordmark-dark.png) | 1648 × 336, PNG RGBA | White version of the extracted wordmark, used by the README `<picture>` element when GitHub is in dark mode. |

- Use descriptive names and document dimensions, pixel format, conversion steps, and destination.
- Prefer formats suitable for the 240 × 320 RGB565 display and account for Flash and internal RAM.
- Preserve editable sources where licensing permits, and record the source and license.
- Never commit device QR secrets, credentials, or personal data in images.

## Music and sound effects

Store reusable music and sound-effect sources in `music/`.

- Document the source, license, sample rate, bit depth, channels, conversion command, and destination.
- Prefer 16 kHz, 16-bit mono PCM when it matches the current BSP audio path.
- Check Flash and internal-RAM cost before embedding audio; stream or chunk long recordings.
- Do not commit media without redistribution permission.
