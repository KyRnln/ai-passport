# Assets

This directory stores reusable fonts, images, music, and sound effects, organized by asset type.

Keep each asset in the matching subdirectory and document its destination, naming, integration method, and source/license. Do not mix binary assets with Markdown documentation.

## Fonts

Store reusable font files and generated font sources in `fonts/`.

| File | Type | Use and source |
| --- | --- | --- |
| `fonts/HYPixel11pxU-2.ttf` | TTF, TrueType outlines | Source font for the current UI: Hanyi Pixel 11 px U (`HYPixel 11px U`, Version 9.00.00), an 11 px pixel-grid Chinese face. It is a **commercial Hanyi typeface**: its `name` table (ID 13) refers to `http://hanyi.com.cn/law.php` for license terms, so embedding or redistributing its glyph data requires a Hanyi license. Not committed here; supply your own authorized copy to regenerate. |
| [`fonts/app_font_26.c`](fonts/app_font_26.c) | LVGL 9 font, 4 bpp with only full-on/full-off pixels, 26 px | All main text: titles, metric values, settings rows, top bar and provisioning body. 26 px is exactly 2x the design grid below. |
| [`fonts/app_font_13.c`](fonts/app_font_13.c) | LVGL 9 font, 4 bpp with only full-on/full-off pixels, 13 px | Hints, notes and message text, at the font's design grid size. |
| [`fonts/proggy_16.c`](fonts/proggy_16.c), [`fonts/proggy_32.c`](fonts/proggy_32.c) | LVGL 9 fonts, 1 bpp, 16/32 px | Previous ASCII-only pixel fonts, retained as reference assets and no longer compiled into the application. |

The current fonts are generated by this repository's own converter (`fontTools` plus a
built-in scanline rasterizer), because `lv_font_conv` needs Node, which is not
available in this environment. Run from the repository root:

```bash
python tools/gen_cjk_font.py --font <path>/HYPixel11pxU-2.ttf \
  --size 26 --name app_font_26 --output assets/fonts/app_font_26.c --snap
python tools/gen_cjk_font.py --font <path>/HYPixel11pxU-2.ttf \
  --size 13 --name app_font_13 --output assets/fonts/app_font_13.c --snap
```

The design grid matters more than the name: `HYPixel 11px U` has `upem = 1000` and
places one design pixel every 77 units, so its em grid is **13 px** (77 x 13 = 1001), not
11 px. Rendering it at 11 px or 22 px maps one design pixel onto 1.69 screen pixels, so
every glyph edge anti-aliases into gray; generate at multiples of 13 px instead. `--snap`
pixel mode additionally thresholds coverage to fully-on/full-off and rounds each advance to
a whole pixel, so glyphs land exactly on the panel grid and text is pixel-exact. Line height
and baseline are taken from the subset's real ink bounds (plus a 2 px leading) instead of
the font's `hhea`, whose 1.31 em line box pushed every glyph down inside an over-tall box.
Both sizes together cost about 90 KB of Flash and are registered in `main/CMakeLists.txt`.

The character inventory is derived from the string literals of `main/*.c` (comments are
ignored), so regenerating after any text change fails loudly instead of shipping a
missing glyph; `--print-inventory` lists the covered characters and `--dump-codepoint`
prints one glyph's bitmap for review without a device.

[`fonts/ProggyCleanSZ-1.ttf`](fonts/ProggyCleanSZ-1.ttf) is the source of the retained
reference fonts: ProggyClean by Tristan Grimmer (2004), a free pixel font whose license
permits redistribution; it is not shipped to the device directly.

- Use descriptive names that include the family, weight, size, and format when relevant.
- Document the source, license, character range, conversion command, and expected destination.
- Check Flash and internal-RAM impact before adding a font; the ESP32-C3 has no PSRAM.
- Do not commit fonts whose license does not permit redistribution.

## Images

Store reusable source images and generated display assets in `images/`.

| File | Dimensions and format | Use and source |
| --- | --- | --- |
| [`images/home.jpg`](images/home.jpg) | 3840 × 2160, JPEG | Product hero image embedded in both project README files to foreground AI Passport and its open, maker-oriented identity. |
| [`images/readme-hardware-specs.png`](images/readme-hardware-specs.png) | 2172 × 724, PNG RGBA | Optional technical infographic retained as a reference asset; it is no longer used as the homepage hero. Generated for this repository with the built-in image generation tool on 2026-09-17; the six labels and values were checked against the documented hardware contract. |
| [`images/logo-wordmark.png`](images/logo-wordmark.png) | 1648 × 336, PNG RGBA | Transparent black wordmark extracted from the repository's original `images/logo.png`; embedded in both project README files for light backgrounds. |
| [`images/logo-wordmark-dark.png`](images/logo-wordmark-dark.png) | 1648 × 336, PNG RGBA | White version of the extracted wordmark, used by the README `<picture>` element when GitHub is in dark mode. |

- Use descriptive names and document dimensions, pixel format, conversion steps, and destination.
- Prefer formats suitable for the 240 × 320 RGB565 display and account for Flash and internal RAM.
- Preserve editable sources where licensing permits, and record the source and license.
- Never commit device QR secrets, credentials, or personal data in images.

## Music and sound effects

Store reusable music and sound-effect sources in `music/`.

- Document the source, license, sample rate, bit depth, channels, conversion command, and destination.
- Prefer 16 kHz, 16-bit mono PCM when it matches the current BSP audio path.
- Check Flash and internal-RAM cost before embedding audio; stream or chunk long recordings.
- Do not commit media without redistribution permission.
